# MoonCat V3 implementation plan

> Execute inline using executing-plans and test-driven-development, with an independent final review.

**Goal:** Reliable selection and bounded recovery behind the existing frontend.
**Architecture:** Pure policy + request ownership; Android adapters retain playback and rendering.
**Tech stack:** Kotlin 2.3, coroutines 1.8.1, Android Media3, JUnit.
**Spec:** docs/superpowers/specs/2026-11-13-mooncat-v3-design.md

## Global constraints
Preserve frontend layouts, package identity, providers, language preferences and the owner’s 1080p / 1–6 GB limit. Build a 3.0.0-alpha.1 candidate; do not claim stable release or measured device performance.

## Review focus
Unknown seed counts remain different from advertised zero. Dead 1080p must not defeat viable 720p within one audio tier. Canceled request cleanup must not clear newer ownership. Discovery can retract all results. Player disposal must stop old watchdogs.

## Tasks
- [ ] Add source availability regressions to MoonCatSourcePolicyTest; observe failures, unify ranking and verify existing policy tests.
- [ ] Add empty/retracted discovery regression to PlaybackSourceSessionTest; observe failure, bound selection and run ranking off the main dispatcher.
- [ ] Add RecoveryRequestGateTest for overlapping requests, invalidation and late completion; implement pure gate and integrate with controller recovery, manual source/episode changes and lifecycle. Reset SourceFailoverSession on manual choice.
- [ ] Verify tests and assets, review diff independently, document exact results and remaining device checks. Prepare V3 candidate version and delivery artifact.
